# Пазлы

Спокойная детская PWA-игра для возраста 3–5 лет. React, strict TypeScript и Vite; полностью клиентская, без аккаунтов, сервера и передачи фотографий в сеть.

[Открыть игру](https://testmovielucky.github.io/KidsPuzzles/) · [Репозиторий](https://github.com/testMovielucky/KidsPuzzles)

## Архитектура

```text
src/
  app/          маршруты и глобальные настройки
  components/   общие кнопки, диалоги и карточки
  pages/        Home, Category, MyPuzzles, PuzzleGame
  puzzle/       чистые правила игры и управление деталями
  storage/      адаптер IndexedDB
  images/       обработка и оптимизация фотографий
  audio/        необязательный SoundService
  data/         каталог встроенных изображений
  styles/       дизайн-токены и адаптивная вёрстка
public/assets/puzzles/  локальные иллюстрации
```

## Выбор зависимостей

| Библиотека                | Назначение и причина                                                                    |
| ------------------------- | --------------------------------------------------------------------------------------- |
| React + TypeScript + Vite | UI, строгие типы, локальная разработка и статическая сборка                             |
| React Router, HashRouter  | Готовая маршрутизация; refresh вложенных экранов работает на GitHub Pages               |
| Dexie                     | Типизированные Blob-записи и версионирование IndexedDB, за отдельным storage-адаптером  |
| vite-plugin-pwa / Workbox | Генерация manifest, service worker и предварительного офлайн-кэша                       |
| Radix Dialog              | Управление фокусом, Escape и доступность modal / bottom sheet без тяжёлой UI-библиотеки |
| Vitest + fake-indexeddb   | Проверки правил snap и жизненного цикла локальных фотографий                            |

Лицензии основных библиотек — MIT; Workbox — MIT. Точные версии фиксируются в package-lock.json. Анимации — CSS. Pointer Events и transform не требуют отдельной drag-and-drop библиотеки. Автоматический center crop через браузерный image decoder и Canvas изолирован в адаптере, чтобы позже добавить ручное кадрирование; библиотека ради этой простой операции не нужна.

Документация: [React Router](https://reactrouter.com/api/declarative-routers/HashRouter), [Dexie](https://dexie.org/docs/), [Vite PWA](https://vite-pwa-org.netlify.app/frameworks/react), [Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog).

## Запуск

Требуется Node.js 24 LTS (24.15+) и npm. Версия для CI зафиксирована в workflow; `.node-version` и `.nvmrc` указывают ту же LTS-ветку.

```sh
npm install
npm run dev
npm run typecheck
npm test
npm run build
npm run preview
```

PWA и офлайн проверяются на production preview, не на dev-сервере.

## Что реализовано

- Четыре категории: «Сказки», «Животные», «Машины», «Мои пазлы».
- 14 встроенных тестовых картинок. Финальные иллюстрации отложены по просьбе пользователя.
- Сложность 3×3, 4×4 и 5×5. Фигурные детали с выступами и выемками, прямой наружный край. Одна картинка на пазл: SVG `clipPath` обрезает её по контуру каждой детали, включая продолжение фотографии в выступах. Отдельные файлы кусочков не создаются.
- Pointer Events с pointer capture, отдельный визуальный слой через `translate3d` и `requestAnimationFrame`. React обновляется при размещении, а не при каждом движении пальца.
- Настраиваемый `snapThreshold` в `GameBoard`, по умолчанию 0.65 стороны ячейки. Учитывается центр перетаскиваемой детали и актуальное положение поля.
- Отмена жеста при `pointercancel`, потере захвата, смене ориентации и уходе со страницы. Случайное второе касание игнорируется.
- Альтернативное управление: нажать на деталь, затем на её ячейку. Доступно с клавиатуры.
- Закреплённые детали блокируются, после завершения появляется цельная картинка, анимация и кнопки повторения / выбора другого пазла.
- Просмотр оригинала в modal: для MVP выбран устойчивый к прерыванию touch toggle-сценарий.
- Локальные синтезированные звуки Web Audio, открываемые пользовательским жестом. Отдельные звуковые файлы не нужны. Отключение сохраняется в localStorage; фотографий там нет.

Контуры находятся в `src/puzzle/geometry.ts`: каждая внутренняя граница задаёт противоположные выступ / выемку соседей. Симметричные кривые Безье совпадают при обратном обходе. `PieceArtwork` одинаково отображает контур в лотке, на поле и при drag. Симметричный запас вокруг ячейки оставляет выступы видимыми; snap по-прежнему ориентируется на центр ячейки, в том числе при захвате за выступ. Для drag-копии создаётся отдельный ID обрезки. [Документация SVG clipPath](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/clipPath).

В книжном режиме телефона верхняя строка объединяет возврат, название, звук и подсказку. Поле занимает доступную высоту над лотком с учётом безопасных областей экрана и открытых панелей браузера (`svh`). При ширине до 700 px и высоте до 760 px лоток показывает три детали в один ряд; на более высоком экране — шесть в два ряда. Пустые места сохраняют размер лотка при перелистывании, а поворот устройства меняет число видимых деталей без сброса прогресса.

## Фотографии и приватность

`src/images/prepareImage.ts` принимает `File`, использует нативный декодер браузера (включая EXIF-ориентацию в современном Safari), выполняет center crop и сохраняет JPEG до 1024×1024 с качеством 0.84. Отдельный preview — до 320×320. Маленькие фотографии не увеличиваются. Прозрачность заполняется молочным цветом; метаданные исходника не копируются.

Перед сохранением взрослый видит результат и может отменить операцию. Ручное позиционирование crop оставлено на следующий этап; `centerCrop` отделён от декодирования и UI. Входной файл ограничен 30 МБ, после декодирования отклоняются изображения более 60 мегапикселей. Нативный декодер всё равно может временно занимать память пропорционально исходнику — большие фото нужно проверить на целевых устройствах.

JPEG, PNG и другие форматы, которые декодирует браузер, работают без сервера. HEIC зависит от версии Safari и способа передачи файла из медиатеки; если формат не открылся, интерфейс предлагает JPEG, PNG или снимок экрана.

`src/storage/puzzles.ts` скрывает Dexie и предоставляет `getUserPuzzles`, `getUserPuzzle`, `saveUserPuzzle`, `deleteUserPuzzle`. Хранятся Blob, thumbnail, размер, дата и ID. Object URL освобождаются после закрытия экрана / preview. Удаление требует подтверждения и касается только локальной копии в игре.

Ни фотография, ни её имя не передаются в сеть. Встроенные картинки, шрифты и иконки входят в сборку; сторонних CDN-запросов, аналитики и сетевых API нет. Данные относятся к конкретному устройству и origin. Очистка данных Safari, удаление PWA или нехватка места могут удалить пазлы; исходники в медиатеке останутся. [Политика хранения WebKit](https://webkit.org/blog/14403/updates-to-storage-policy/).

## PWA и офлайн

`vite-plugin-pwa` генерирует manifest и Workbox service worker. Precache включает HTML, JS, CSS, локальные шрифты, иконки и **все** встроенные картинки, даже ещё не открытые пользователем. После завершения первой установки service worker приложение доступно без сети. Первый запуск без интернета невозможен.

В настройках появляется сообщение о готовности к офлайн-работе. Обновление использует режим `prompt`: новая версия не перезагружает игру во время сборки. Предложение обновиться появляется вне игрового экрана; можно выбрать «Позже».

Для работы service worker нужен HTTPS (либо localhost для разработки). `npm run preview` показывает production-сборку. При тестировании через IP локальной сети на обычном HTTP PWA не зарегистрируется — проверять установку и офлайн удобнее на GitHub Pages.

## GitHub Pages

1. Создайте GitHub-репозиторий и загрузите исходники вместе с `package-lock.json` в ветку `main`. `node_modules` и `dist` не коммитятся.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. После push в `main` workflow `.github/workflows/deploy.yml` выполнит `npm ci`, тесты, TypeScript, сборку и публикацию.
4. URL готовой игры появится в GitHub Pages и результате workflow. Для pull request отдельно запускается `.github/workflows/check.yml` без публикации.

`actions/configure-pages` автоматически передаёт `base_path` в Vite: работают проектные адреса `/KidsPuzzles/`, корневой `username.github.io` и настроенный домен. `HashRouter` использует адреса вида `/#/category/animals` и `/#/play/lion?size=3`; refresh не требует серверного rewrite. [Документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

Удалённый репозиторий: `testMovielucky/KidsPuzzles`. GitHub Pages настроен на GitHub Actions; адрес игры — `https://testmovielucky.github.io/KidsPuzzles/`. Состояние публикации видно во вкладке Actions репозитория.

Проверка сборки для подпапки локально:

```powershell
$env:BASE_PATH = '/KidsPuzzles/'
npm run build
npm run preview
# Открыть http://localhost:4173/KidsPuzzles/
```

Для обычной локальной сборки удалите переменную `BASE_PATH`. В bash используется `BASE_PATH=/KidsPuzzles/ npm run build`.

## Установка на iPhone / iPad

1. Откройте опубликованную HTTPS-ссылку в Safari с доступом к интернету.
2. Дождитесь загрузки. В настройках игры проверьте готовность к работе без интернета.
3. Выберите **Поделиться → На экран Домой**. Если доступен переключатель **Открывать как веб-приложение**, оставьте его включённым. Нажмите **Добавить**.
4. Откройте «Пазлы» с домашнего экрана, затем проверьте игру в авиарежиме.

Если пункта добавления нет, проверьте список действий меню «Поделиться». [Инструкция Apple](https://support.apple.com/en-tm/guide/iphone/iphea86e5236/ios).

## Проверки

`npm test` проверяет правила пазла, точное совпадение кривых соседних деталей, прямой внешний край, координаты изображения внутри фигурного контура, точность snap при захвате за выступ, отсутствие повторного размещения, перемешивание, crop, хранение / удаление Blob и жизненный цикл drag в jsdom. Это автоматические проверки логики, не тесты реального Safari.

`npm run build` запускает strict TypeScript и production build. `npm run format:check` проверяет оформление исходников.

Перед использованием на устройствах пройти [ручной чек-лист](docs/DEVICE-QA.md): Safari и standalone, portrait / landscape, перетаскивание, отмена жестов, загрузка фото с EXIF / HEIC, VoiceOver, увеличение текста и офлайн после перезапуска. Физические iPhone / iPad в текущем запуске не проверялись.

## Замена временных изображений

Каталог находится в `src/data/puzzles.ts`, картинки — в `public/assets/puzzles/`. Сейчас используются простые SVG-заглушки для отладки механики. Когда будут готовы иллюстрации, добавьте квадратные WebP / JPEG до 1024×1024 и поменяйте пути в каталоге. WebP, JPEG и PNG уже включены в precache. Держите каждую картинку меньше 3 МБ — верхнего лимита precache.

Не создавайте отдельные файлы деталей: движок использует одну исходную картинку на каждый пазл. `scripts/create-placeholders.mjs` — вспомогательный скрипт тестовых заглушек, он не запускается при build. Не запускайте его поверх финальных SVG с теми же именами.

Иконка PWA — простая геометрическая пиктограмма `public/icon.svg`; PNG-размеры пересоздаются командой `npm run icons`. Шрифт Nunito поставляется локально через Fontsource (SIL Open Font License). Sharp используется только инструментом подготовки иконок и не входит в клиентский bundle. Prettier, Testing Library и jsdom нужны только для разработки.
